DeskLine — audit sink swappability (D7 of the plan's Audit dimension)
Date:  2026-08-22
Result: PASS. One config line moves every audit event from the database to a
        file and back, with no call site touched, and the events are provably
        absent from the table while the flag points at the file.

────────────────────────────────────────────────────────────────────────
THE MECHANISM
────────────────────────────────────────────────────────────────────────

  `setAuditSink` accepts any function matching the `AuditSink` contract:

    type AuditSink = (record: AuditLogRecord & {
      timestamp: string; requestId?: string; userId?: string;
    }) => void | Promise<void>;

  So swapping destinations is a question of which function is registered,
  never of editing a caller. `src/lib/audit-sinks.ts` adds an NDJSON file
  sink; `src/lib/audit.ts` chooses between it and the Prisma sink from
  `aiden.config.ts` → `audit.sink`.

  NDJSON rather than a JSON array: an array has to be rewritten to stay
  valid, and an append-only log that is rewritten on every write is not
  append-only. One object per line survives truncation and is what log
  rotation expects.

  The sink never throws. `auditLog()` is fire-and-forget — the SDK does
  not await it and will not see a rejection — so an escaping failure would
  be an unhandled rejection and a swallowed one would lose events
  silently. Every failure goes through the app logger instead.

  No route, no component. `auditLog({ event, resourceId, metadata })` in a

────────────────────────────────────────────────────────────────────────
4. WHAT THE SWAP DOES NOT COVER — stated, not discovered later
────────────────────────────────────────────────────────────────────────

  It changes where events are **written**. The org-scoped viewer still
  reads `prisma.auditLog` through `listOrgAuditEntries`, so while the file
  sink is active the `/admin/audit` page goes quiet: new events are
  landing somewhere it does not look. That is the honest consequence of a
  write-side swap and is documented in `src/lib/audit-sinks.ts` rather
  than left for someone to trip over.

  A deployment that genuinely wanted file-based audit would need a reader
  for it too, or would accept that the in-app viewer covers only the
  database era.

  Retention is unchanged by any of this and remains consumer-owned: for
  the file sink it is log rotation, for the Prisma sink a scheduled
  truncation past the compliance window. Neither belongs inside
  `aiden-security`.

────────────────────────────────────────────────────────────────────────
5. A TYPE-SYSTEM NOTE WORTH KEEPING
────────────────────────────────────────────────────────────────────────

  `aiden.config.ts` closes with `as const`, so `audit.sink` carries the
  literal type of whichever value is written today. A directly-assigned
  const narrows to that same literal, and TypeScript then rejects the
  comparison against the other value:

    error TS2367: This comparison appears to be unintentional because the
    types '"prisma"' and '"file"' have no overlap.

  The branch is not impossible — it is unreachable until someone flips the
  flag, which is the whole point of the flag. Resolved with a function
  whose declared return type is the union, since a return type is not
  narrowed at the call site. A cast would also have silenced it, but a
  cast asserts something about the value where this asserts something
  about *when it is known*. The config literal stays free of casts either
  way, which matters because the CLI parses that file.
