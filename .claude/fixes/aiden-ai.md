# aiden-ai Fixes

- **[2026-08-04]** `client.complete({ responseSchema })` against the Anthropic provider returned `response.parsed: undefined` and `response.text` wrapped in a ```` ```json ... ``` ```` markdown fence, causing a hand-rolled `JSON.parse(response.text)` fallback to throw `SyntaxError: Unexpected token '`'`. Root cause, confirmed by reading `dist/anthropic.js`: the adapter's `toRequest()` never forwards `responseSchema` into the Anthropic API request at all (only `tools`/`temperature`/`system`/`messages`/`max_tokens`/`stream` are sent) — there's no tool-forcing, no native structured-output mode. `responseSchema` is purely a client-side flag: if set and `text` is non-empty, the adapter does a bare `try { parsed = JSON.parse(text) } catch { parsed = undefined }`. So `response.parsed` only succeeds if the model's raw reply *happens* to be valid bare JSON — entirely dependent on the caller's own prompt instructing that, with zero help from the SDK. A system prompt that only said "respond with the requested structured fields" wasn't explicit enough; the model added a markdown fence, which broke the naive parse. Fix (`src/lib/tickets.ts`): strengthened the system prompt to explicitly forbid markdown/backticks/commentary and spell out the exact JSON shape inline — this alone did NOT fully solve it; Claude models reliably wrap JSON replies in a ```` ```json ``` ```` fence even when told not to. Added one narrow, well-scoped fallback (`tryParseFencedJson`): strip a leading/trailing triple-backtick fence and retry `JSON.parse` — not a broader regex/NLP extraction pipeline, just unwrapping a known formatting artifact around content that IS the requested structured JSON. If still unparseable after that, throw — a genuine AI-call failure, never silently coerced. Worth knowing for any future `responseSchema` use with this provider: it is a parse hint, not an API contract enforced by the model provider, and its own bare `JSON.parse` has no fence-awareness at all.
