# aiden-security Fixes

- **[2026-08-04]** Following the `@upstart13-com/aiden-security` README's own top-line middleware example verbatim — `export { securityHeaders as middleware } from "@upstart13-com/aiden-security/middleware";` — breaks EVERY request in the app: every route returns 500 or a bad redirect, with the dev overlay showing `TypeError: Expected an instance of Response to be returned` from the edge sandbox adapter. Root cause: `securityHeaders` (see `dist/middleware.js`) is a **factory** — `securityHeaders(options = {})` returns the real `(req) => NextResponse` middleware closure; it does not detect being invoked directly as middleware. Re-exporting the factory itself under the name `middleware` means Next.js calls `securityHeaders(req)` per request — treating the `NextRequest` object as the `options` argument — which returns *another function* (the inner closure), not a `Response`. Next's edge runtime then throws exactly the observed error. The README's OWN second example (the "compose with custom logic" one) shows the correct call shape (`const apply = securityHeaders({...}); export const middleware = (req, ev) => apply(req, ev);`) but the first, simpler example is missing the call entirely. Fix: always call the factory, even with no options — `export const middleware = securityHeaders();` in `src/middleware.ts`, never re-export `securityHeaders` itself under the `middleware` name.
