# AIDEN CLI Fixes

- **[2026-08-04]** `npx @upstart13-com/aiden-cli doctor` (and by extension `upgrade`, which reads the same config) fails on essentially every real `aiden.config.ts` with `aiden-cli: failed to parse aiden.config.ts literal: Bad control character in string literal in JSON at position N`. Root cause: `parseTsConfigLiteral` in `aiden-cli@2.0.1`'s `dist/cli.js` strips line comments with `source.replace(/\/\/.*$/gm, "")` before JSON-parsing the object literal — a regex that matches `//` anywhere on a line, including *inside a string value*, not just at a real `//` comment start. `app.url: "https://example.com"` (the stock scaffold's own placeholder value) gets truncated to `"https:` mid-string, producing invalid JSON. Confirmed by reproducing the CLI's own transform against the shipped default config — no local edits were needed to trigger it; any `aiden.config.ts` containing an `http://`/`https://` string anywhere breaks the same way. Not fixable from the app side without falsifying the config (e.g. removing the URL's scheme) — that trades a correct config value for a green checkmark from a buggy tool, which we opted not to do (see `docs/aiden-doctor-output.md` for the real captured output and reasoning). Structural fix belongs upstream in `aiden-cli`: strip comments with a proper tokenizer/regex that respects string boundaries (e.g. only strip `//` when not preceded by an odd number of unescaped quotes on that line), or require `.js`/`.json` config for `doctor`/`upgrade` until the `.ts` literal parser is hardened.
